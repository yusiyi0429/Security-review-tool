# ADR-0002：增加当前用户安装器交付

- 状态：Accepted
- 日期：2026-07-22
- 决策者：产品需求反馈；具名工程与安全负责人待指派
- 关联：REQ-001, US-001, AC-001, SRS-F-001
- 补充：ADR-0001 的运行时架构保持不变，本 ADR 仅替代其“第一版只交付便携 ZIP”的交付决策

## 背景

试点版以自包含 ZIP 交付，用户必须下载、解压、定位并运行 EXE。该流程对非开发用户过于笨重，也增加了从压缩目录直接运行、漏解压依赖和升级时残留旧文件的概率。产品仍需保持免管理员、无服务、无自动更新和纯本地数据边界。

## 决策

1. 正式发布同时提供单文件 `Setup.exe` 和便携 ZIP，安装器作为默认下载项。
2. 使用 Inno Setup 生成安装器；安装范围为当前用户，目标目录是 `%LOCALAPPDATA%\Programs\SecurityReviewTool`，不得触发 UAC。
3. 安装器只封装已经过 allowlist、manifest、SBOM 和哈希验证的便携 ZIP 内容，不建立第二套应用发布流程。
4. 使用固定 `AppId` 支持原位升级；创建开始菜单快捷方式，桌面快捷方式可选，安装完成页可直接启动。
5. 卸载只删除程序文件、快捷方式和当前用户卸载登记，默认保留 `%LOCALAPPDATA%\SecurityReviewTool` 中的加密历史和设置，防止意外数据丢失。
6. 生产安装器必须进行 Authenticode 签名并发布 SHA-256；未签名安装器仅允许用于明确标识的授权试点环境。
7. 不增加服务、驱动、计划任务、开机启动项、自动更新器、机器级注册表或防火墙规则。

## 备选方案

### A. 继续只提供 ZIP

拒绝作为默认交付。维护成本最低，但没有解决用户反馈，升级时也容易混合新旧文件。ZIP 保留为免安装备用方式。

### B. MSIX

暂不采用。MSIX 的签名、证书信任和包身份要求会提高当前试点发布门槛，且可能影响现有任意本地文件选择与 AppContainer 方案。获得稳定企业签名和分发基础设施后可重新评估。

### C. 机器级 MSI

拒绝。通常需要管理员权限，与 REQ-001 冲突，也没有服务或共享组件需要机器级安装。

## 影响与验证

- 用户可以双击完成安装并直接启动，升级由固定安装目录和 `AppId` 管理。
- 发布机需要 Inno Setup 6 或 7；生产发布还需要可用的 Authenticode 签名工具和证书。
- clean VM 门禁必须覆盖安装、首次启动、原位升级、卸载、静默安装参数、无 UAC/服务/计划任务/机器级写入，以及卸载后用户数据保留。
- 安装器并不改变主进程、worker、AppContainer、数据目录和网络边界。
