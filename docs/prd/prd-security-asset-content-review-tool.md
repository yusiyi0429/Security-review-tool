## 1. 目的与范围

### 1.1 业务目标

本项目没有独立 BRD。为保持需求可追溯性，本 PRD 将本次访谈确认的目标登记为本地业务目标：

| 目标 ID | 业务目标 |
| --- | --- |
| BRD-OBJ-001 | 在项目资产对外发布前，帮助内部审查人员发现、分类并精确定位危险敏感信息，降低非预期披露风险。 |
| BRD-OBJ-002 | 以轻量、可下载、无需管理员权限的 Windows 本地客户端完成审查，不建设中心服务。 |
| BRD-OBJ-003 | 对扫描覆盖范围、失败项、规则版本和复核过程提供可解释、可追溯的证据，避免产生“绝对安全”的错误结论。 |

### 1.2 问题陈述

待发布资产的格式和结构多样，可能包含源码、配置、Office 文档、JAR、Docker/OCI 镜像、模型文件、压缩包及通用二进制。人工逐项检查成本高，容易遗漏嵌套内容、隐藏内容、历史镜像层和语义型风险。现有 Excel 清单描述了资产类型和敏感类别，但属于自然语言政策，不能直接、稳定地驱动扫描程序。

产品需要在本地静态解析最终待发布产物，组合确定性检测器与内网 LLM 语义复核，输出完整命中内容、精确位置、覆盖缺口和人工复核记录。产品只负责扫描、定位和辅助复核，不负责发布拦截或自动整改。

### 1.3 源表分析

工作簿实际包含 3 个可见 Sheet，其中 `Sheet3` 为空，因此有 2 个有效内容 Sheet：

- `Sheet1` 定义 11 类资产及其审查要求：提示词、工作流、数据集、Skills、交付指导书、场景化方案、知识库/经验库、模型、工程工具、本体、镜像文件。访谈已确认原表“镜像文件”指 Docker/OCI 容器镜像。
- `Sheet2` 对 `Sheet1` 第二列引用的 8 类敏感信息进行详细展开：
  1. 密钥和认证信息；
  2. 银行内网和基础设施信息；
  3. 真实或疑似真实个人信息；
  4. 账户与金融数据；
  5. 生产日志和会话数据；
  6. 安全凭据关联信息；
  7. 风险与安全控制细节；
  8. 受第三方保密或许可限制的内容。
- `Sheet1` 备注区域在资产行之间合并，包含银行名称、内部产品名称、客户或开发人员名称和 IP 地址等示例，按访谈结论视为项目级受限实体及网络信息示例。
- 源表对数据集、知识库、模型和镜像只列出了窄范围专项要求。访谈已确认：8 类敏感信息适用于所有资产；`Sheet1` 的资产规则只能增加专项检查和风险权重，不能关闭基础检查。
- “内网 IP”与“公网 IP”表述存在歧义。访谈已确认：除批准的安全占位符外，公网和内网 IP 均扫描并报告，分类和风险等级分开处理。
- “知识库经大模型转换”和“只发布微调模型”属于资产合规条件，不等同于敏感内容。产品将其作为独立的“资产合规发现”报告，并以 Manifest 证据为准。

### 1.4 产品原则

1. **低漏报优先**：候选风险可以降级或折叠，但不得由 LLM 静默删除。
2. **没有静默跳过**：任何不支持、失败、排除、超限或未完成的内容都必须进入覆盖缺口。
3. **只读与不执行**：所有资产均视为不可信输入，只进行隔离、静态、只读解析。
4. **结论有边界**：零命中只能表示“在本次成功覆盖范围内未发现风险”，不能表示绝对安全或保证可发布。
5. **完整内容可见**：内部审查人员可以在客户端和 XLSX 中查看完整命中值与上下文。
6. **纯本地产品**：无中心服务、用户体系、跨电脑同步或外部遥测；只有语义候选可按规则发送给内网 LLM。

### 1.5 第一版范围

#### 范围内

- Windows 10/11 x64 简体中文图形化便携客户端。
- 最终待发布文件、目录和导出产物的本地扫描。
- 约 10 GB、10 万文件的单次任务。
- 文件与目录选择、拖拽、进度、取消、只读预览、复核、复扫和 XLSX 导出。
- 8 类通用敏感信息、资产专项规则和资产合规规则。
- 本地多检测器初筛及 OpenAI 兼容内网 LLM 的受限语义复核。
- Python、JAR、Docker/OCI、Open XML、可提取文本的 PDF、常见文本/结构化文件、压缩包及通用二进制。
- 文件名、路径、元数据、隐藏内容、NTFS 备用数据流和可解析嵌入内容。
- 本地加密历史、人工复核状态、例外、差异比较及严格缓存。
- 离线导入的版本化规则包和标准 Excel 规则模板。

#### 范围外

- 自动阻止发布、审批发布、修改资产、删除风险或自动脱敏。
- 绝对安全证明或“保证可发布”的结论。
- 中心服务、SSO、RBAC、项目隔离、中心审计和跨电脑历史同步。
- macOS、Linux、Windows ARM、32 位 Windows、Windows 7/8。
- 机器级安装器、后台服务及自动更新器；提供无需管理员权限的当前用户安装器和便携 ZIP。
- 外部 LLM、外部遥测、外部崩溃上报或任意互联网访问。
- 直接连接本地 Docker 引擎；只扫描导出的 Docker TAR 或 OCI 目录。
- Git 历史解析；意外出现 `.git` 时报告并列为未完整覆盖。
- 完整 Java 反编译、通用反汇编或动态执行分析。
- 模型权重的语义泄漏证明；只检查安全可读的头部、元数据、相邻配置和 Manifest 证据。
- 图片 OCR、截图文字识别及图片型 PDF 的 OCR。
- 旧版 `.doc`、`.xls`、`.ppt` 的正文解析。
- 破解或扫描密码未知的加密文件。
- JSON、PDF、HTML 等报告导出；第一版只导出 XLSX。

### 1.6 关键假设

- 内部资产可以导出为最终待发布文件或目录。
- 内网 LLM 提供 OpenAI 兼容接口。
- 资产不包含需要解密的文件；若意外出现，按扫描不完整处理。
- 正式审查以最终待发布产物为输入；开发目录扫描只能作为提前自查。
- 所有客户端使用者均为可信内部人员，应用不实施查看权限；但不同电脑之间不自动共享数据。

## 2. 目标、指标与护栏

### 2.1 主要指标

| 指标 ID | 指标 | 第一版目标 |
| --- | --- | --- |
| METRIC-001 | 确定性高风险检出率 | 在版本化回归语料中，密钥、证件号、银行卡号、IP 等确定性样例 100% 检出。 |
| METRIC-002 | 语义型风险召回率 | 在人工标注的脱敏或合成语料中不低于 95%。 |
| METRIC-003 | 覆盖缺口披露率 | 所有不支持、排除、损坏、超限、加密或解析失败样例 100% 出现在“未覆盖内容”。 |
| METRIC-004 | 定位正确率 | 回归语料中的预期命中均定位到要求的文件、结构或字节位置。 |

### 2.2 次要指标

| 指标 ID | 指标 | 第一版目标 |
| --- | --- | --- |
| METRIC-005 | 启动性能 | 参考电脑冷启动不超过 5 秒。 |
| METRIC-006 | 资源占用 | 空闲内存不超过约 300 MB；扫描峰值内存不超过约 1.5 GB。 |
| METRIC-007 | 扫描性能 | 参考电脑上，10 GB、10 万文件的纯本地阶段在 30 分钟内完成；LLM 时间单独统计。 |
| METRIC-008 | 取消响应 | 点击取消后 2 秒内停止调度新文件，并安全结束当前解析。 |
| METRIC-009 | 规则回归 | 每个规则包版本发布前通过同一套自动化回归语料。 |

参考电脑定义为 Windows 10/11 x64、4 核 CPU、8 GB 内存和 SSD。

### 2.3 产品护栏

- 不执行资产、宏、脚本、JAR、容器、Git Hook 或安装程序。
- 不因 LLM 低风险结论删除候选发现。
- 不把确定性高风险完整值发送给 LLM。
- 不把资产正文、完整 LLM 请求或敏感值写入普通日志。
- 不静默排除文件、解析区域或失败的模型复核。
- 不将资产来源文本作为 Excel 公式或外部链接写入报告。
- 不向内网 LLM 以外的网络目标发送数据。

## 6. 功能行为（FRS-lite）

### 6.1 主流程

1. 审查人员启动便携客户端。
2. 选择或拖入最终待发布的文件、目录、Docker TAR 或 OCI 目录。
3. 客户端读取 Manifest；缺失时由审查人员在界面选择资产类型、映射混合路径并补充合规证据。
4. 客户端展示活动规则版本、内网 LLM 状态、文件预清单、用户排除项和预计覆盖范围。
5. 客户端生成稳定文件清单并开始隔离、流式、只读解析。
6. 本地检测器对解析内容执行通用、专项和合规检查。
7. 只将语义候选及有限上下文发送给内网 LLM；失败候选保留待复核。
8. 客户端展示扫描完成状态、覆盖缺口、发现分组及精确位置。
9. 审查人员在只读预览中查看完整内容并记录人工判定。
10. 审查人员可以导出六 Sheet XLSX 报告。
11. 资产整改后重新扫描；客户端比较发现差异并使失效例外重新进入复核。

### 6.2 扫描状态

| 状态 | 定义 |
| --- | --- |
| 未开始 | 已创建任务但尚未读取输入。 |
| 扫描中 | 正在枚举、解析、本地检测或 LLM 复核。 |
| 完成 | 所有计划解析和必需的语义候选复核成功完成；可有风险发现，但无覆盖缺口。 |
| 部分完成 | 存在排除、不支持、失败、超限、加密、不稳定文件或未完成语义复核。 |
| 已取消 | 用户取消；已处理结果可保留，但结论不能视为完整扫描。 |
| 失败 | 任务级错误导致无法形成可信输入清单或扫描结果。 |

### 6.3 发现项数据

每个发现位置至少包含：

- 稳定发现 ID 和敏感值指纹；
- 扫描批次、资产 ID、资产类型和资产版本；
- 敏感内容发现或资产合规发现；
- 敏感类别、规则 ID、检测器 ID 和规则版本；
- 风险等级：严重、高、中、低、提示；
- 检测置信度：高、中、低；
- 完整命中值和有限上下文；
- 文件路径及格式专用精确位置；
- LLM 是否调用、模型标识、提示模板版本、结构化理由和复核状态；
- 人工判定、理由、操作者、时间；
- 例外范围、批准理由和有效期；
- 新增、持续、消失或重新出现等差异状态。

风险等级与置信度相互独立，LLM 只能提出调整建议并提供理由，不能覆盖规则审计轨迹。

### 6.4 格式与解析边界

| 内容类型 | 第一版覆盖 |
| --- | --- |
| 文本、源码和配置 | 完整扫描常见文本、Markdown、JSON、YAML、XML、CSV、日志、配置和源码；支持 UTF-8、UTF-16、GBK/GB18030 等编码。 |
| Python | 扫描源码、注释、字符串、配置引用，定位到行列；不执行。 |
| Open XML | 完整解析 `.docx`、`.xlsx`、`.pptx` 的正文、元数据、批注、公式、隐藏区域、外部链接描述和可解析嵌入内容。 |
| 宏启用 Office | 扫描普通 Open XML 内容并从宏二进制提取可见字符串；不执行宏。 |
| 旧版 Office | `.doc`、`.xls`、`.ppt` 不支持正文解析，必须进入未覆盖清单。 |
| PDF | 解析可提取文本、元数据和可解析附件；图片型内容不 OCR，并列入覆盖说明。 |
| ZIP/TAR/GZ 等归档 | 受限递归解包，防止路径穿越、逃逸、压缩炸弹和过深嵌套。 |
| JAR | 扫描 Manifest、配置、资源、嵌套归档和 `.class` 常量池字符串；不完整反编译。 |
| Docker/OCI | 扫描导出配置、环境变量、标签、历史命令和全部文件层，包括后续层已删除的内容；不连接引擎或启动容器。 |
| 通用 PE/ELF 二进制 | 扫描元数据、资源和可提取 ASCII/Unicode 字符串，定位到字节偏移；不反汇编。 |
| 模型文件 | 扫描安全可读的文件名、头部、元数据、相邻配置、分词器、模型卡和 Manifest；不反序列化危险格式，不证明权重无训练数据泄漏。 |
| 加密文件 | 不破解、不支持密码输入；检测到后标记扫描不完整。 |
| Git 元数据 | 不解析历史；意外出现 `.git`、bundle 或对象库时报告为意外高风险结构并标记未完整覆盖。 |
| 图片和图片型 PDF | 不执行 OCR，标记为部分未覆盖。 |

### 6.5 内容范围

内容范围包括但不限于：

- 文件正文、源码注释、字符串、配置键和值；
- 文件名、目录名、归档条目名和嵌套路径；
- 文档作者、公司、主题、批注、隐藏 Sheet/行/列、公式和外部链接描述；
- JAR Manifest、包名、类名、资源名和常量池；
- Docker 配置、标签、环境变量、历史命令及每一层文件系统；
- NTFS 隐藏文件、系统属性文件和备用数据流；
- 可安全提取的二进制资源、字符串和元数据。

### 6.6 规则模型

规则由以下部分组成：

1. 8 类全资产通用敏感信息；
2. 资产类型专项规则和风险权重；
3. 资产合规规则；
4. 受限实体词典，包括银行全称、简称、旧称、变体、内部项目、平台、特性、客户和人员名称；
5. 明确批准的安全占位符；
6. 检测器配置、严重度、置信度和人工复核策略；
7. 第三方授权来源和内容指纹。

补充业务规则：

- 所有非批准占位符的公网和内网 IP 均报告，类别和严重度可不同。
- 只有明确批准的占位数据可以豁免；LLM 不得自行判断姓名、账号或地址为虚构。
- 受限实体词典命中一律报告，即使实体名称本身公开。
- 第三方内容只定位并提示人工核验；没有可靠授权证据时不能自动判断合规或侵权。
- 知识库转换、模型微调和第三方授权以 Manifest 或可验证元数据为证据；缺失时报告“无法验证”。

### 6.7 规则生命周期

- 当前工作簿作为初始业务来源，不直接作为长期执行格式。
- 标准规则 Excel 模板至少包含：`规则包信息`、`敏感类别`、`资产专项规则`、`受限实体词典`、`安全占位符`、`检测器配置`。
- 规则维护流程将模板转换为带版本和完整性/签名信息的离线规则包。
- 客户端内置默认规则，允许导入新的统一规则包。
- 历史规则只读保留以复现旧扫描；新扫描默认使用最新有效规则。
- 本地补充词典允许存在，但必须在扫描和报告中明确标识。

### 6.8 LLM 复核边界

- 接口为用户配置的 OpenAI 兼容内网端点、模型和凭据。
- 凭据使用 Windows 系统秘密存储，不写入明文配置或日志。
- 确定性高风险直接报告，不发送给 LLM。
- 只有依赖语境的候选项连同最小必要上下文发送给 LLM；无关敏感字段先遮盖。
- LLM 无文件访问、工具调用、代码执行或网络扩展能力。
- 资产内容被放在固定数据边界中，模型被明确要求忽略其中的指令。
- 输出必须满足固定结构；非法、拒绝、超时或疑似受注入影响的输出回退到人工复核。
- 记录模型标识和提示模板版本，不记录含完整敏感原文的请求正文日志。

### 6.9 人工复核与例外

人工状态包括：待复核、已确认风险、误报、已批准例外、已整改等待复扫。

例外必须绑定：

- 资产 ID 和版本；
- 文件路径和发现位置；
- 命中内容指纹；
- 规则版本；
- 批准理由、当前 Windows 用户和有效期。

内容、位置或规则变化后例外自动失效。全局白名单只能通过统一规则包变更。

### 6.10 XLSX 输出

导出报告固定包含：

1. `扫描摘要`；
2. `敏感内容发现`；
3. `资产合规发现`；
4. `未覆盖内容`；
5. `文件清单`；
6. `复核记录`。

资产来源内容全部以纯文本单元格写入，禁止公式、宏和可点击外部链接。导出前提示报告包含完整敏感信息，由操作者明确选择保存位置。

### 6.11 替代和错误流程

- **空输入**：禁止启动扫描并说明需要选择文件或目录。
- **路径无权限**：逐项列入未覆盖；若无法建立可信根目录清单则任务失败。
- **文件变化**：自动重扫一次；再次变化则该文件不稳定，任务部分完成。
- **用户排除**：允许按路径、扩展名或大小设置；所有排除留痕且任务部分完成。
- **解析失败或不支持**：任务继续处理其他文件，失败项进入未覆盖。
- **LLM 失败**：本地结果保留；有未完成语义候选时任务部分完成，允许单独重试。
- **取消**：停止新调度、安全结束当前解析、清理临时内容并保留已取消记录。
- **缓存不匹配**：重新执行受影响阶段，不降级为旧结果。
- **规则包无效**：拒绝启用并继续保留当前有效规则。
- **磁盘空间不足**：停止创建临时内容，清理本任务缓存并报告失败原因。

## 7. 非功能性产品约束

### 7.1 性能

- 参考设备冷启动不超过 5 秒。
- 空闲内存不超过约 300 MB，扫描峰值不超过约 1.5 GB。
- 本地阶段处理 10 GB、10 万文件不超过 30 分钟。
- 使用流式读取，不把大型文件完整载入内存。
- LLM 延迟和失败率单独展示，不计入本地扫描性能。
- 单次只需支持一个活动扫描任务；历史任务可查看和导出。

### 7.2 安全与隐私

- 全部输入视为不可信；解析器使用受限子进程和资源上限。
- 永不执行资产，永不自动访问文档外部链接。
- 临时解包内容在任务结束、取消或失败后清理。
- 完整发现和历史使用当前 Windows 用户保护机制加密。
- 默认保留 90 天，可配置为 30 天、180 天或永久，并支持一键清理。
- 本地历史只提供可追溯性，不宣称防删除、防管理员篡改或不可抵赖。
- 除内网 LLM 外无网络访问、无遥测、无自动崩溃上报。
- 日志默认不包含资产正文、完整敏感值、LLM 请求正文或可暴露敏感信息的完整路径片段。

### 7.3 可用性

- 简体中文界面和简体中文报告。
- 支持文件/目录选择和拖拽。
- 扫描期间界面保持响应并显示阶段、文件、字节、失败数和 LLM 队列。
- 结果可按类别、风险等级、置信度、资产类型、复核状态和差异状态筛选。
- 同一敏感值在界面分组，所有位置可展开。
- 默认应用内只读高亮预览；外部打开前提示风险。
- 支持“在资源管理器中定位”。
- 第一版遵循 Windows 系统缩放和基础键盘导航；不设独立 WCAG 认证目标。

### 7.4 可靠性

- 单文件解析失败不得导致任务或应用崩溃。
- 扫描完成状态由覆盖证据决定，不能由发现数量决定。
- 历史扫描不可被新任务覆盖。
- 严格缓存键包含文件、解析器、客户端、规则、检测器、提示模板和模型标识。
- 扫描和导出过程应可重复验证输入摘要和规则版本。

## 8. 分析、遥测与支持

### 8.1 本地事件

客户端仅在本地记录以下运行事件，用于历史和诊断：

- 任务创建、开始、取消、完成或失败；
- 解析器成功、失败、超时或超限；
- 检测器和 LLM 阶段的计数与耗时；
- 规则导入、启用或拒绝；
- 人工复核和例外变更；
- XLSX 导出时间、任务 ID、目标文件摘要和导出行数。

本地事件不得包含资产正文或完整敏感值。

### 8.2 仪表盘与告警

- 不建设中心仪表盘或告警服务。
- 当前任务界面显示本地错误、覆盖缺口和 LLM 连接状态。
- 客户端支持人员依赖用户主动导出的脱敏诊断包。

## 10. 依赖与发布

### 10.1 依赖

- 一个可访问的 OpenAI 兼容内网 LLM 端点、模型标识和凭据方案。
- 安全规则负责人维护的标准 Excel 模板、规则包版本和签名/完整性校验流程。
- 脱敏或合成的跨格式回归语料及人工标注语义样本。
- Windows 10/11 x64 测试设备。
- 具备条件时提供企业代码签名证书；若暂缺，分发说明必须提供文件摘要和来源验证方式。

### 10.2 发布策略

推荐分两阶段发布：

1. **内部试点**：由少量资产发布前审查人员验证格式覆盖、误报、性能、LLM 接口和 XLSX 可用性。
2. **内部普及**：试点验收通过后，以便携压缩包和统一规则包向所有内部人员分发。

第一版不自动更新。客户端升级通过重新下载便携包完成；规则通过离线导入更新。

### 10.3 支持准备

- 提供快速开始说明、支持格式清单、未覆盖含义和报告结论口径。
- 提供规则包导入说明和 LLM 连接配置说明。
- 提供脱敏诊断包导出流程。
- 提供扫描失败、部分完成、规则无效和 LLM 不可用的处理指引。
